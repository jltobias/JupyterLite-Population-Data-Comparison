# Method and import contract

## Native counts and spherical overlap

All accepted data store **people per cell**, never density. A rectangular comparison allocates `native_count × spherical_overlap_area / spherical_native_cell_area`, assuming uniform population within each cell. Spherical rectangle area is proportional to longitude width times the difference of sine latitude. The stable implementation also handles tiny polar rectangles. This assumption cannot recover within-cell settlement patterns.

Regular grids store north-up row-major values, native origin, spacing and dimensions. Only intersecting native rows/columns are visited. Grids retain their different offsets; no common-grid resampling occurs. Each grid has at most 262,144 cells, with at most 32,767 pixels on either display axis. The original nonoverlapping rectangular-cell API remains available with a 2,000-cell limit. Every accepted cell must have representable positive bounds and area.

Coverage is the spherical fraction of the analysis rectangle containing numeric source cells. Numeric zero counts contribute coverage. Null is NoData and contributes neither population nor numeric-cell coverage. No numeric overlap returns `None` / `null`, displayed as “No coverage.” `prepared_coverage` separately reports geometric overlap with the available grid rectangle, so an area extending outside the excerpt is explicit. Tiny floating-point coverage excess is clamped to one.

## Interpreting the four products

WorldPop Global2 is a January 1, 2025 residential estimate and R2025A v1 is an alpha public release. GRID3 Nigeria is scaled to July 2025 and uses a different model and inputs. Within Nigeria its NaN means mapped unsettled; outside the national boundary it denotes outside coverage. These remain nulls rather than zero counts. LandScan Global 2020 describes ambient population averaged over 24 hours. GHS-POP 2025 is a residential projection using GPWv4.11 demographics and GHSL built-up information; it declares no NoData, so zero, including water, is numeric coverage.

WorldPop and GRID3 share producers/inputs. GHS-POP shares GPW demographic inputs. Product agreement is not independent accuracy validation. The same nominal year does not imply equal reference dates, concepts, inputs or uncertainty. Coverage is not a confidence measure.

## Import contract

The viewer begins with a value-free catalog of canonical metadata, source geometry, TIFF asset sizes/hashes and native block tables. Typed/drawn/use-map bounds update a draft and acquisition estimates before counts load. The Lagos default automatically loads four bounded native windows. Orange dashed drafts never change committed blue bounds, images, totals or exports. All staged layers and native PNG images pass before one successful comparison commit. Bounds edits, replacement, Cancel, errors and the 120-second comparison or active import-phase timeout terminate stale workers; prior valid results remain available. A cache bounded to 16 MiB of count values and 16 windows keys prepared pixels by asset SHA and snapped native window. Exact-box totals are recalculated on reuse. "Compare already loaded windows" explicitly uses existing support without acquiring new pixels.

Local/public HTTPS GeoTIFF imports share the native-window validator and decoder. Review declarations, copy the current draft study bounds if desired, select **Plan native window**, then **Read selected native window**. Successful imports commit their own selected box with the image and counts. Templates supply citations, not independent source identification; copied bundle receipts and verification claims are removed. File/window declarations retain stable input URL or filename, asset size, geometry, selected window, TIFF metadata and reader/method. Local bytes stay in the browser; no server receives the file. The pinned LandScan mirror is an editable remote template, not a claim that four global products stream remotely.

Remote public HTTPS reads require exact HTTP206 responses, exposed Content-Range and a strong ETag or Last-Modified. Validator and total size must agree on every request. Last-Modified has weaker, second-level precision. Reads are serialized and bounded; malformed/overlong/truncated bodies and ignored HTTP200 Range responses fail. An ignored HTTP200 body is cancelled without consumption. No If-Match header is added, avoiding unsupported mirror preflights. Credentials and query-token/signed URLs are rejected; transient redirect URLs are never recorded. The stable user URL remains in the acquisition declaration. Partial reads do not verify a full-file SHA; catalog hashes are expected asset identities, separate from full-file preparation receipts. No full-file fallback, proxy, TLS bypass or resampling is performed.

Plans show cells, Float64 output-count memory (browser arrays/images add overhead), selected compressed bytes and decoded block bytes. Actual bytes include headers and repeated metadata and are reported separately. Strips span full source rows, so a narrower longitude box may reduce output while preserving selected compressed cost. The companion [JupyterLite-STAC-Browser](https://github.com/jltobias/JupyterLite-STAC-Browser) inspired bbox acquisition; the MIT Range reader and bounded LZW adaptation retain a pinned revision/path in the vendor notices.

Accepted TIFFs are little-endian, single-band, PixelIsArea, explicitly EPSG:4326 and north-up with positive pixel scale and one tiepoint. Counts must be stored directly, with finite nonnegative values or a declared NoData sentinel (including NaN). Unsupported CRS, rotation/shear, PixelIsPoint, scale/offset, internal masks, alpha/extra samples, SubIFDs, multiple primary images and unsupported sample encodings are rejected. External `.msk` sidecars cannot be read; declare that the file has none. Overviews in the main IFD chain are inspected but never used for calculations. Sparse blocks retain declared NoData, including NaN.

Limits: local file 2 GiB (remote source size may exceed 2 GiB); native output 262,144 cells, with at most 32,767 pixels on either display axis; metadata 8 MiB, 1,024 entries per directory and 32 directories; each decode block 16 million pixels; selected compressed blocks 64 MiB; selected decoded blocks 128 MiB; actual transfer 128 MiB/job, 16 MiB/request, 4096 requests/job, 20 seconds/request and 120 seconds per planning or acquisition phase (idle plan review is excluded). Only uncompressed, LZW and Deflate counts are accepted, with bounded decompression. Choose a smaller area or prepare a tiled excerpt when a file exceeds these limits. No resampling is used to fit a limit. Cancellation terminates the worker; errors retain valid layers and analysis.

Small rectangular GeoJSON imports remain supported: WGS84 FeatureCollection without a CRS override, one closed axis-aligned Polygon ring per feature, numeric `properties.population`, required metadata, at most 2 MB and 2,000 nonoverlapping cells, each no more than 5° wide/high. A labelled synthetic fixture is supplied only for this lesson/test contract.

## Reproducibility and exports

`data/population.json` contains canonical lossless count/null arrays for unchanged Book/Lab lessons. Viewer startup does not request it. `data/population-catalog.json` contains no pixel values; its deterministic standard-library generator validates TIFF layouts, native geometry and hashes, and explicit preparation stages it with source outputs. Normal builds copy the checked-in catalog without network or raster-package requirements. `data/real/` contains TIFF excerpts, acquisition receipts, native transforms, source/output hashes, STAC metadata, independent source expectations and ORNL validation receipts. `scripts/prepare_population.py` explicitly acquires/extracts sources with optional NumPy/rasterio dependencies; normal builds never refresh sources. Input cache files stay outside publication.

JSON and CSV retain full metadata, grid identity, active bounds, counts, coverage, native cell count and method. CSV's `metadata_json` preserves extra notices. SVG embeds complete results in its description and displays source credits, license, dates/concepts and coverage. Display rounding does not affect export precision. NoData remains distinct from zero in all formats.
